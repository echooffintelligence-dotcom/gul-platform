Всё, что можно было сделать кодом, сделано кодом. Здесь только то, что кодом
сделать физически нельзя: это действия в панели Supabase и в настройках
развёртывания. Без пунктов 1 и 2 приложение запустится и будет работать, но
данные останутся в браузере и в памяти процесса — то есть исчезнут при
перезапуске и не будут видны другим слушателям.

Порядок важен: сначала 1, потом 2.


--------------------------------------------------------------------------------
1. ВЫПОЛНИТЬ SQL-СХЕМУ  (обязательно, 2 минуты)
--------------------------------------------------------------------------------

  1. Откройте https://supabase.com/dashboard → ваш проект
  2. Слева: SQL Editor → New query
  3. Скопируйте ЦЕЛИКОМ содержимое файла  supabase/schema.sql  из этого архива
  4. Вставьте и нажмите Run

Что произойдёт: создадутся недостающие таблицы, к существующим добавятся
недостающие колонки, включится RLS и заведутся Storage-бакеты audio и covers.

ВАЖНО, ПРОЧТИТЕ.
Я проверил ваш проект Supabase. Таблицы tracks, releases и workspace_snapshots
в нём УЖЕ ЕСТЬ, но другой формы — например, в tracks есть только id и title,
а owner_id, audioUrl, coverUrl и остальных полей нет вовсе. Поэтому schema.sql
написан не как «создать таблицы», а как миграция: недостающие колонки
добавляются через ALTER TABLE ... ADD COLUMN IF NOT EXISTS. Существующие данные
скрипт не трогает.

Единственное исключение — он удалит из workspace_snapshots строки без владельца.
Там лежит общая demo-строка 'gul-local-demo', в которую писали ВСЕ пользователи
разом: это и была главная дыра. Приложение пересоздаст снапшот при первом входе.

Проверка после выполнения — запустите в том же SQL Editor:

    select tablename, rowsecurity from pg_tables
     where schemaname = 'public'
       and tablename in ('tracks','releases','gzt_votes','workspace_snapshots',
                         'artist_links','playlists','play_history');

Должно вернуться СЕМЬ строк, и в колонке rowsecurity у всех — true.
Если строк меньше семи или где-то false — схема применилась не полностью,
запустите скрипт ещё раз и пришлите текст ошибки.


--------------------------------------------------------------------------------
2. ОТКЛЮЧИТЬ ПОДТВЕРЖДЕНИЕ EMAIL  (обязательно, если нужен вход сразу)
--------------------------------------------------------------------------------

  Supabase → Authentication → Sign In / Providers → Email
  → выключить "Confirm email" → Save

Иначе после регистрации Supabase не выдаёт сессию, пользователь остаётся без
токена, и приложение переводит его в локальный режим: публикации сохраняются
только в его браузере.


--------------------------------------------------------------------------------
3. ЗАДАТЬ ПЕРЕМЕННЫЕ ОКРУЖЕНИЯ  (обязательно для production)
--------------------------------------------------------------------------------

Скопируйте .env.example в .env.local и подставьте значения своего проекта:

    NEXT_PUBLIC_SUPABASE_URL=https://ваш-проект.supabase.co
    NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_...

Оба значения берутся в Supabase → Project Settings → API Keys.

Если деплой на Vercel — те же две переменные добавьте в
Project Settings → Environment Variables и сделайте redeploy.

Сейчас в коде есть значения по умолчанию, чтобы demo работало без .env.
Для production задайте переменные явно: иначе при смене проекта приложение
продолжит ходить в старый.


--------------------------------------------------------------------------------
4. ПРОВЕРИТЬ БАКЕТЫ  (1 минута, после пункта 1)
--------------------------------------------------------------------------------

  Supabase → Storage

Должны быть два бакета: audio и covers, оба помеченные Public.
Их создаёт schema.sql, но если в проекте стояли особые настройки — проверьте
глазами. Публичность нужна, чтобы у загруженного трека был постоянный URL,
доступный всем слушателям. Запись при этом закрыта: политика разрешает класть
файлы только в папку с именем собственного uid.


--------------------------------------------------------------------------------
5. РОТАЦИЯ КЛЮЧА  (по желанию, но я бы сделал)
--------------------------------------------------------------------------------

Publishable-ключ по своей природе публичен — он и должен уходить в браузер,
и сам по себе утечкой не является. Проблема была в другом: до сих пор RLS не
был включён, а значит любой, кто открывал сайт и заглянул в исходники, мог этим
ключом читать и перезаписывать данные напрямую через REST API.

После пункта 1 ключ становится безопасным: доступ ограничивает RLS.
Но если сайт был доступен посторонним, я бы всё равно перевыпустил ключ:

  Supabase → Project Settings → API Keys → Rotate

После ротации обязательно обновите NEXT_PUBLIC_SUPABASE_ANON_KEY (пункт 3).


--------------------------------------------------------------------------------
6. ЧЕГО Я НЕ СМОГ ПРОВЕРИТЬ — ПРОВЕРЬТЕ ВЫ
--------------------------------------------------------------------------------

Честно, чтобы вы не считали проверенным то, что не проверено.

У меня нет аккаунта в вашем Supabase, поэтому я не мог войти в приложение
и получить настоящий JWT. Полностью проверено следующее:

  ПРОВЕРЕНО МНОЙ:
    - все запросы БЕЗ токена отклоняются (10 сценариев атак, см. журнал);
    - запрос с поддельным токеном отклоняется;
    - интерфейс, «Моя волна», похожие артисты, плейлисты, бейдж ИИ,
      ссылки артиста, обводка выделения — вживую в браузере;
    - tsc --noEmit и npm run build — без ошибок.

  НЕ ПРОВЕРЕНО, ТРЕБУЕТ ВАШЕГО АККАУНТА (сделайте после пункта 1):
    a) Зарегистрируйтесь в приложении и опубликуйте трек с аудиофайлом.
       Ожидается сообщение «аудио доступно всем по постоянному URL».
       Если увидите жёлтое предупреждение про локальную копию — значит
       Storage не принял файл: проверьте пункты 1 и 4.
    b) Перезагрузите страницу и запустите этот трек ещё раз — он должен играть.
       Затем откройте его в другом браузере или в режиме инкогнито:
       трек обязан играть и там. Это главный тест «аудио не теряется».
    c) Оцените релиз по ГЗТ дважды подряд с одного аккаунта.
       Количество голосов должно остаться прежним, а оценка — замениться.
       Если счётчик голосов растёт — напишите мне, значит голоса не схлопываются.
    d) Зайдите вторым аккаунтом и убедитесь, что чужие карточки, приватные
       плейлисты и чужой workspace не видны и не редактируются.


--------------------------------------------------------------------------------
7. ЗАПУСК
--------------------------------------------------------------------------------

    npm ci
    npm run build
    npm run start

Требуется Node.js 20 или новее.

Проверка типов отдельной командой:

    node ./node_modules/typescript/bin/tsc --noEmit

Обратите внимание: из next.config.mjs убран флаг ignoreBuildErrors, поэтому
сборка теперь падает на ошибках типов. Так и задумано — раньше «зелёный»
npm run build не значил ничего.
